# Release Process

The following checklist has all the steps needed to publish a new release in both GitHub and crates.io using `release-plz` and the GitHub UI.

- [ ] Check the last CI run on the release branch succeeded.

- [ ] Checkout the branch to release from and pull the latest changes:

    ```sh
    git checkout BRANCH && git pull origin BRANCH
    ```

- [ ] In your local clone, create a new branch:

    ```sh
    git checkout -b release-vX.X.X
    ```

- [ ] Bump the version in `Cargo.toml` (both `workspace` and `workspace.dependencies` fields).
      The new version number must follow [Semantic Versioning](https://semver.org/).
      You can use `release-plz update` to automatically do this while checking for semver violations.
      There's also `cargo-semver-checks` to validate the chosen version.

- [ ] Verify the workspace compiles.
      This will also update the `Cargo.lock` with the new version

    ```sh
    cargo check --workspace --all-targets
    ```

- [ ] Cut the changelog.

- [ ] Commit and push all changes and open a new PR.

- [ ] Once it's reviewed and merged, wait for the [Release-plz](./.github/workflows/release-plz.yml) workflow to finish.

- [ ] Check on crates.io that [the new version of the `eigensdk` crate](https://crates.io/crates/eigensdk/versions) was published.
      The other crates are required by this one, so if this one was published, the rest were too.

- [ ] Go to [the releases page](https://github.com/Layr-Labs/eigensdk-rs/releases). A draft release should have been created by `release-plz`.

- [ ] Adjust the release target or previous tag if needed.
      The release title can also be updated.

- [ ] Merge the autogenerated changelog with the new version's section of the `CHANGELOG.md`.

- [ ] Add any missing descriptions to the changelog items. It's recommended that every item that's not in "Documentation" or "Other Changes" has a description of what changed and instructions on how to migrate. You can encounter examples in previous changelog entries.

- [ ] Commit the updated changelog and submit a PR.

- [ ] Sync the release draft description with the changelog and save the draft.

- [ ] Once the draft is reviewed and the PR merged, publish the release.
